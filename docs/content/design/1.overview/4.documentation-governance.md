# Documentation Governance

Documentation Governance は、Document Driven Monorepo における docs の構造原則です。

docs は、理想設計、標準手順、現在スコープを分けて管理します。AI Agent と人間が同じ docs を読めば、何を目指し、今回どこまで作り、どの手順に従うかを判断できる状態を保ちます。

## 基本原則

- docs は実装前の合意を置く場所として扱う。
- 理想形と現在スコープを混ぜない。
- 繰り返し使う標準手順と一時的なタスク事情を混ぜない。
- AI Agent が推測で実装範囲を広げないように、Scope、Out of Scope、Acceptance Criteria を明示する。
- 実装結果が docs の合意内容を変える場合は、該当する docs を更新する。

## 領域の責務

### design

`design` は理想形と最終形を書く場所です。責務境界、アーキテクチャ、設計原則、長期的な判断基準、将来構成を記述します。

`design` には、現在の進捗、暫定実装、未完了タスク、個別ブランチの事情を書きません。どうしても実装段階に触れる必要がある場合は、短い Stage や注記に留めます。

利用者が採用方針を回答した後は、未採用パターンを design の本文に同列の候補として残しません。採用済みの UX、アーキテクチャ、責務境界は決定事項として書きます。

未採用案を残す必要がある場合は、Out of Scope、Decision Note、Alternatives Considered のいずれかに短く記述します。

### operations

`operations` は繰り返し使う標準手順を書く場所です。初期設定、日次、週次、月次、アドホック対応、環境情報、ドキュメント更新手順を記述します。

`operations` には、開発途中の一時的な回避策、未完了タスク、個別ブランチの事情を書きません。担当者が変わっても同じ結果になる手順だけを置きます。

AI Agent が docs を更新する具体的な作業手順は `operations/documentation` に置きます。

### delivery

`delivery` は現在の開発を管理する場所です。ロードマップ、現在スコープ、理想設計との差分、タスク、受け入れ条件、検証方法を記述します。

AI Agent が実装前に読む入口は `delivery/current-scope` です。delivery にない作業を始める場合は、先に Current Scope、task list、対象タスクのいずれかを更新します。

## 更新先の判断

- 理想設計が変わる: `design` を更新する。
- 標準手順が変わる: `operations` を更新する。
- 今回作る範囲、作らない範囲、完了条件が変わる: `delivery` を更新する。
- 実装だけが変わり docs の合意内容が変わらない: docs 更新は不要でもよい。

## 既存ページ優先

AI Agent は、既存ページで表現できる内容について新規ページを作成しません。

新規ページを作成してよいのは、次の条件をすべて満たす場合に限ります。

- 既存ページへ統合すると責務が混ざる。
- 継続的に参照される独立した設計または手順である。
- Current Scope、MVP、Initial Setup、Development Roadmap のいずれにも自然に収まらない。
- 新規ページを作る理由を更新内容に明記できる。

代表的な更新先は次の通りです。

| 内容 | 優先更新先 |
| --- | --- |
| アプリや外部サービスの初期設定、環境変数、起動確認 | `operations/initial` |
| 全体の段階計画 | `delivery/development-roadmap` |
| 現在作る範囲、作らない範囲 | `delivery/current-scope` |
| MVP の目的、成果物、対象外 | `delivery/scopes/1.mvp/overview` |
| MVP のタスク | `delivery/scopes/1.mvp/task-list` または `tasks` |
| MVP の完了条件 | `delivery/scopes/1.mvp/acceptance-criteria` |

## 矛盾した場合の優先順位

docs 間で矛盾がある場合、実装時は次の順序で優先します。

1. `delivery/current-scope`
2. `delivery/task`
3. `design`
4. `operations`

`design` と `delivery` が矛盾する場合、実装時は `delivery` を優先します。ただし、理想設計が古くなっている可能性があるため、必要に応じて `design` の更新を提案します。

## 最低構成

新規プロジェクトでは、少なくとも次の docs を用意します。

- `design/overview/vision`
- `delivery/current-scope`
- `operations/getting-started`

この最低構成がない場合、AI Agent は実装を始める前に docs の初期作成を提案します。
