# Documentation Governance

docs は、設計、運用、開発スコープを分けて管理します。AI Agent は、変更内容に応じて適切な領域を更新します。

## design

`design` は理想形と最終形を書く場所です。責務境界、アーキテクチャ、原則、将来構成を記述します。

現在の進捗、暫定実装、タスク状態は書きません。どうしても実装段階に触れる必要がある場合は、短い Stage や注記に留めます。

## operations

`operations` は繰り返し使う標準手順を書く場所です。初期設定、日次、週次、月次、アドホック対応、環境情報、ドキュメント更新手順を記述します。

開発途中の一時的な回避策、未完了タスク、個別ブランチの事情は書きません。

## delivery

`delivery` は現在の開発を管理する場所です。ロードマップ、現在スコープ、理想設計との差分、タスク、受け入れ条件、検証方法を記述します。

AI Agent が実装前に読む入口は delivery です。delivery にない作業を始める場合は、先にスコープまたはタスクを更新します。

## 更新判断

- 理想設計が変わる: `design` を更新する。
- 標準手順が変わる: `operations` を更新する。
- 今回作る範囲が変わる: `delivery` を更新する。
- 実装だけが変わり docs の合意内容が変わらない: docs 更新は不要でもよい。
