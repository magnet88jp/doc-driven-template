# Monorepo

このリポジトリは、Nuxt 4 アプリケーション、ドキュメントサイト、共有パッケージ、AWS SAM による運用基盤を同じ docs の下で扱う monorepo として設計します。

monorepo の基本構成は事前に決定済みです。AI Agent は、新しい実装依頼を受けたときに構成を質問するのではなく、この構成を前提にします。この構成で実現できない、または責務境界に矛盾する場合のみ、利用者へ確認します。

## 想定構成

- `apps/web`: ユーザー向け Nuxt 4 アプリケーション。
- `docs`: Nuxt Content ベースの開発・運用ドキュメントサイト。
- `packages/shared`: 型、契約、ユーティリティ、ドメイン非依存の共有コード。
- `infra/aws/sam`: AWS SAM による API、非同期処理、権限、イベント、監視などの基盤定義。

## 現在の構成

現在のリポジトリには、次の領域が存在します。

- `apps/web`: Nuxt 4 と Nuxt UI を使うユーザー向け Web アプリケーション。
- `docs`: Nuxt 4、Nuxt Content、Nuxt UI を使うドキュメントサイト。
- root `package.json`: `apps/web`、`docs`、`infra/aws/sam` を呼び出す script の入口。
- root `pnpm-workspace.yaml`: workspace 全体の pnpm 設定。

次の領域は、必要になった時点で追加します。

- `packages/shared`: 複数領域で共有する型、DTO、schema、error contract。
- `infra/aws/sam`: AWS Lambda、API Gateway、EventBridge、SQS、DynamoDB、Secrets Manager、IAM などの AWS リソース定義。

## 配置方針

アプリ固有の UI、API、状態管理は `apps/*` に置きます。複数アプリで共有する契約や型は `packages/shared` に置きます。環境差分やデプロイ手順は `infra` または `operations` に置き、アプリケーションコードに埋め込みません。

Nuxt アプリケーションのホスティング設定は、対象アプリ配下の `amplify.yml` に置きます。`apps/web/amplify.yml` は Web アプリ、`docs/amplify.yml` は docs サイトの AWS Amplify Hosting 設定です。

AWS リソースの定義は `infra/aws/sam` に置きます。Nuxt の `server/api` は Web アプリに閉じる軽量な API や画面都合の API に限定し、独立したバックエンド責務、外部 webhook、非同期処理、永続化、権限管理は AWS SAM 側へ寄せます。

## 依存方向

依存方向は、アプリケーションから共有パッケージへ向けます。共有パッケージは特定アプリの UI や実行環境に依存しません。`docs` は実装に依存せず、合意された設計と運用を記述します。

標準の依存方向は次の通りです。

```text
apps/web
  -> packages/shared
  -> AWS services through public API endpoints

docs
  -> docs/content

infra/aws/sam
  -> packages/shared when shared contracts are needed
```

`packages/shared` は `apps/web`、`docs`、`infra/aws/sam` の UI や実行環境に依存しません。

## AI Agent へのルール

新しいディレクトリやパッケージを追加する場合は、先に delivery の対象タスクで目的と責務を確認します。既存構成にない責務を追加する場合は、design の monorepo または architecture に反映します。

アーキテクチャや配置先を質問する前に、このページと `design/architecture/system-overview`、`design/architecture/responsibility-boundary` を確認します。
