# Harness Design

Harness は Loop Engineering の実行入口です。現在の実装は `scripts/loop-harness.mjs` にあります。

Harness は実装判断の主体ではありません。Reality Source を読み、変更を検知し、後続 Agent が判断できる状態へ変換します。

## Inputs

| Input | Purpose |
| --- | --- |
| `docs/content/**/*.md` | Reality Source documents. |
| Git diff or GitHub event | Changed docs detection. |
| `STATE.md` | Existing candidate, attempts, approvals, verifier evidence. |
| Environment variables | Budget, max attempts, autonomy enable flag, approved item ID. |
| `SKILL.md` | Agent-facing shortcut for mappings and command sets. |

## Outputs

| Output | Purpose |
| --- | --- |
| `STATE.md` candidate items | L1 output consumed by L2. |
| Handoff entries | Reasons the loop cannot continue autonomously. |
| Verifier command output | Evidence for completion or failure. |
| Future PR metadata | Branch name, item ID, commands, docs updates, risk notes. |

## Modes

| Mode | Command | Current Behavior |
| --- | --- | --- |
| L1 | `pnpm loop:l1` | Detect docs changes, classify impact, append candidate items to `STATE.md`. |
| L2 | `pnpm loop:l2` | Gate implementation behind `LOOP_APPROVED_ITEM_ID` and `LOOP_ENABLE_AUTONOMY=l2`. |
| L3 | `pnpm loop:l3` | Gate full automation behind explicit enablement. Disabled by default. |
| Task Validation | `pnpm loop:validate-task <task-id>` | Resolve one task ID and fail on unknown ID, missing required schema fields, invalid `status`, invalid `autonomy`, invalid `source_of_truth`, missing `verification_commands`, or missing `handoff_conditions`. |
| Task Validation | `pnpm loop:validate-tasks` | Validate schema-managed task pages. Legacy MVP task pages without schema fields are skipped until their migration scope. |
| Verifier | `pnpm loop:verify:docs`, `pnpm loop:verify:web` | Run documented command sets and fail on first failing command. |

## Environment Variables

| Variable | Meaning |
| --- | --- |
| `LOOP_BUDGET_USD` | Hard budget cap for the run. Default is `10`. |
| `LOOP_ESTIMATED_COST_USD` | Estimated cost before execution. If greater than cap, the harness stops. |
| `LOOP_MAX_ATTEMPTS` | Retry cap per candidate. Default is `3`. |
| `LOOP_APPROVED_ITEM_ID` | Candidate item approved by a human for L2 or L3. |
| `LOOP_ENABLE_AUTONOMY` | Must be `l2` or `l3` before those tiers may proceed. |

## Classification Rules

Harness maps Reality Source changes to likely implementation areas:

| Docs Path | Impact |
| --- | --- |
| `docs/content/design/4.loop-engineering/` | Harness, state, workflow, maker-checker rules. |
| `docs/content/design/3.application-design/` | Web app, server API, shared contracts. |
| `docs/content/design/2.architecture/` | Workspace layout, app boundaries, package boundaries. |
| `docs/content/operations/` | Package scripts, repeatable commands, operational workflows. |
| `docs/content/maintenance/` | State transitions, verifier evidence, PR lifecycle. |
| `docs/content/delivery/` | Task-specific implementation scope. |

## Safety Model

- L1 may only update `STATE.md`.
- L2 may modify implementation only for an approved candidate.
- L3 may prepare PRs only after readiness and verifier criteria are met.
- Denylisted paths require handoff.
- Command evidence is mandatory before resolution.
