# Autonomy Tiers

Loop Engineering uses three autonomy tiers. They are stages in one pipeline.

## L1: Impact Analysis

L1 detects Reality Source changes and records candidate items.

Allowed actions:

- Read Git diff and Nuxt Content docs.
- Classify changed docs by impact area.
- Append candidate items, suggested checks, and next gates to `STATE.md`.

Forbidden actions:

- Modify implementation files.
- Mark items resolved.
- Create PRs.

Completion condition:

- `STATE.md` contains candidate items with source docs, impact area, suggested maker action, and verifier expectation.

## L2: Approved Implementation

L2 implements a candidate item approved by a human.

Allowed actions:

- Create or use a working branch.
- Modify docs and code within the approved scope.
- Run verifier commands.
- Prepare PR content.

Required gates:

- `LOOP_APPROVED_ITEM_ID` is set.
- `LOOP_ENABLE_AUTONOMY=l2` is set.
- Attempts for the candidate are fewer than three.
- No denylisted path is required.

Completion condition:

- Maker changes are complete.
- Verifier evidence is recorded.
- Docs and code are aligned.
- PR is ready for human review.

## L3: Full Loop

L3 may perform routine implementation and PR preparation without per-item manual approval, but only for low-risk items.

L3 remains disabled until:

- L1 has produced at least three useful candidate runs.
- L2 has produced repeated PRs with successful verifier evidence.
- Readiness score is 23/25 or higher.
- Denylist and budget enforcement have been proven in CI.
- Human owners explicitly approve the L3 scope.

L3 is never allowed to:

- Merge PRs.
- Modify secrets or authentication paths.
- Expand Current Scope.
- Ignore verifier failures.
