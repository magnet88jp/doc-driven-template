# Maker Verifier Separation

Maker and Verifier are separate roles. The point is not ceremony; it is to prevent completion claims without evidence.

## Maker

Maker implements approved work.

Responsibilities:

- Read Current Scope, target task, related design, operations, maintenance docs, and `STATE.md`.
- Confirm the candidate item is approved for L2 or allowed by L3 policy.
- Keep changes inside scope.
- Avoid denylisted paths.
- Update Reality Source docs when implementation changes the agreed behavior.
- Record assumptions and commands attempted.

Maker must not:

- Decide its own work is complete without verifier evidence.
- Expand scope because implementation is convenient.
- Hide failed commands.

## Verifier

Verifier checks the work from a separate context.

Responsibilities:

- Read the candidate item, diff, acceptance criteria, and related docs.
- Run relevant typecheck, lint, test, build, and task-specific commands.
- Record command evidence.
- Reject the item if evidence is missing or docs and code disagree.

Verifier must not:

- Accept summaries without command output.
- Treat unrun commands as passed.
- Ignore doc-code drift.

## Evidence Standard

An item can move to resolved only when evidence includes:

- command name,
- result,
- relevant output summary,
- failure reason if failed,
- files or docs checked.

If a command cannot run because dependencies or credentials are unavailable, Verifier records the reason and hands off to a human.
