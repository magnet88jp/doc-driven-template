# Responsibility Boundary

責務境界は、実装をどこに置くかを判断するための基準です。

## apps/web

`apps/web` は Nuxt 4 アプリケーションです。ページ、レイアウト、コンポーネント、Web 固有の状態管理、Web に閉じる軽量なサーバー API を担当します。

Web に閉じる表示ロジックは `apps/web` に置きます。複数アプリで共有する型やスキーマは置きません。

`apps/web` の AWS Amplify Hosting 設定は `apps/web/amplify.yml` に置きます。

Nuxt `server/api` は、Web アプリに閉じる API、モック、画面都合の軽量 API に限定します。外部 webhook、永続化、非同期処理、権限管理、外部サービス連携は `infra/aws/sam` の backend API に寄せます。

## docs

`docs` は Nuxt 4、Nuxt Content、Nuxt UI を使うドキュメントサイトです。設計合意、運用手順、開発スコープを担当します。実装の代替ではなく、実装前後の判断材料です。

`docs` の AWS Amplify Hosting 設定は `docs/amplify.yml` に置きます。

## packages/shared

`packages/shared` は共有契約を担当します。DTO、スキーマ、エラー型、共通ユーティリティなど、複数領域で意味を共有するものを置きます。

`packages/shared` は、`apps/web`、`docs`、`infra/aws/sam` から参照される共有コードです。特定アプリの UI、Nuxt runtime、AWS Lambda runtime に依存しません。

## infra/aws/sam

`infra/aws/sam` は AWS SAM による backend API、非同期処理、権限、イベント、監視の定義を担当します。

主な責務は次の通りです。

- API Gateway と Lambda による backend API。
- 外部 webhook の受信。
- EventBridge、SQS、Lambda による非同期処理。
- DynamoDB、Secrets Manager、IAM などの AWS リソース定義。
- `sam validate`、`sam build`、`sam deploy` で検証、ビルド、デプロイできる構成。

## apps/batch

`apps/batch` は標準構成では先に追加しません。定期実行、データ同期、通知、集計などは、まず `infra/aws/sam` の Lambda、EventBridge、SQS として設計します。

AWS SAM では表現しにくい長時間処理、ローカル常駐処理、独立した CLI などが必要になった場合のみ、delivery で目的と責務を明確にしてから `apps/batch` の追加を検討します。

## 境界を越える場合

境界を越える変更は、delivery に影響範囲と検証方法を書きます。恒久的な責務変更であれば design も更新します。

AI Agent は、配置先が曖昧な場合、次の順で判断します。

1. 画面、表示状態、Web に閉じる軽量 API: `apps/web`
2. docs、設計合意、運用手順、開発スコープ: `docs`
3. 共有型、schema、DTO、error contract: `packages/shared`
4. 外部 webhook、backend API、非同期処理、AWS リソース: `infra/aws/sam`
5. AWS SAM では扱いにくい独立処理: `apps/batch` を追加検討
