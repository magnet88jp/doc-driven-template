# PR Automation

PR automation is a later stage of Loop Engineering. It must be built on successful L1 and L2 evidence.

## L2 PR Flow

1. Human approves a `STATE.md` candidate item.
2. Harness opens or selects a branch.
3. Maker implements within the approved scope.
4. Verifier runs required commands.
5. Harness prepares a PR body containing:
   - candidate ID,
   - source docs,
   - changed files,
   - verifier evidence,
   - docs updates,
   - risks and handoff notes.
6. Human reviews and merges.

## L3 PR Flow

L3 may create PRs for low-risk candidates without per-item approval only after promotion criteria are met.

Allowed L3 candidates:

- documentation-only synchronization,
- low-risk script updates,
- verification metadata updates,
- changes that do not touch denylisted paths.

Disallowed L3 candidates:

- authentication,
- secrets,
- deployment credentials,
- broad architecture changes,
- scope expansion.
