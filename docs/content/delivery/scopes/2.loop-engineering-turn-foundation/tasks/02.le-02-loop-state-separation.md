# LE-02 Loop State Separation

## Goal

Loop Engineering の Persistence を、人間が読む最新状況と、Harness が読む機械状態と、履歴として残す run log に分離する。

人間が読む最新状況は、root の `STATE.md` ではなく Nuxt Content の docs page に反映します。`STATE.md` は既存 Harness との互換性と短期運用メモリのために残しますが、ユーザーが日常的に見る dashboard は `docs/content/` 配下に置きます。

## Scope

- 人間向けの最新 dashboard を Nuxt Content の docs page として定義する。
- `STATE.md` の役割を、既存 Harness 互換の短い state mirror と operational shortcut に再定義する。
- `.loop/state.json` の構造を定義する。
- `.loop/runs/*.md` の run log 形式を定義する。
- Harness が machine state と run log から Nuxt Content dashboard を更新する方針を定義する。
- Dashboard UI の情報設計を定義する。
- Harness が state と run log を扱うための最小実装を追加する。
- 既存 `STATE.md` の内容を破壊せず、移行方針を docs に残す。

## Dashboard UI

Dashboard は、AI Agent が何を作ろうとしているか、どこまで進んだか、どこで止まっているかを人間が短時間で把握するための Nuxt Content page です。

First viewport must show:

- Current Turn: 現在の task ID、title、status、autonomy、owner role。
- Intent: 今から作ろうとしているものを 1-2 文で示す。
- Gate State: approved / blocked / verifying / resolved の状態。
- Next Human Action: 人間が次に判断または実行すべきこと。

Below the first viewport:

- Source Docs: task、current scope、related docs へのリンク。
- Scope Boundary: primary area、out of scope、denylist reminder。
- Verification: required commands、last evidence、未実行理由。
- Handoff Queue: blocked item、blocker、必要な人間判断。
- Recent Runs: `.loop/runs/*.md` への参照と要約。

UI principle:

- Dashboard は説明ページではなく運用画面として扱う。
- 最初に current turn と next human action を見せる。
- 長い履歴は折りたたむか下部へ送る。
- status は text だけに依存せず、見出し、table、badge 相当の表現で scan しやすくする。
- secret、credential、token、`.env` values は表示しない。

## Static vs Dynamic Dashboard

この scope では DynamoDB を使った動的 dashboard は採用しません。

理由:

- Loop state は repository 内の docs、machine state、run logs から再生成できる。
- DynamoDB を使うと AWS credentials、IAM、deploy、runtime API、認証の責務が増え、この scope の boundary を超える。
- 人間が見たい最新状況は、Harness が Nuxt Content Markdown を更新する静的 dashboard で十分に実現できる。
- 静的 dashboard は PR diff でレビューでき、docs-driven の思想と相性がよい。

将来、複数 Agent が同時実行され、repository commit だけでは state conflict を扱えなくなった場合に限り、DynamoDB などの外部 state store を別 scope で検討します。

## Out of Scope

- 既存 `STATE.md` の全履歴削除。
- 外部 database の導入。
- GitHub Actions の永続化方式変更。
- PR 自動作成。
- Vue component を使った動的 dashboard UI 実装。
- DynamoDB、API、認証、IAM、deployment を使った dashboard 実装。

## Acceptance Criteria

- Nuxt Content dashboard、`STATE.md`、`.loop/state.json`、`.loop/runs/*.md` の責務が docs に定義されている。
- 人間が読む最新状況は Nuxt Content dashboard に反映する方針になっている。
- `STATE.md` は最新 dashboard ではなく、既存 Harness 互換の state mirror と operational shortcut として扱われる。
- Dashboard UI の first viewport、source docs、scope boundary、verification、handoff queue、recent runs が定義されている。
- Dashboard は DynamoDB ではなく、Nuxt Content Markdown として静的に生成または更新する方針になっている。
- Harness が必要な場合に `.loop` directory を作成できる。
- Harness が machine state、run log、Nuxt Content dashboard を書ける。
- 既存 verifier evidence を失わない移行方針がある。
- denylist と secret policy に反しない。

## Verification

```bash
node --check scripts/loop-harness.mjs
pnpm --dir docs typecheck
```

Verifier は `.loop/state.json` と `.loop/runs/` に secret-like values が含まれていないことも確認します。

Verifier must also confirm:

- Nuxt Content dashboard is the human-facing latest status surface,
- `STATE.md` is not described as the primary human dashboard,
- dashboard UI keeps current turn and next human action visible before long history,
- no DynamoDB, credential, IAM, deployment, or runtime API dependency is introduced for this scope.
