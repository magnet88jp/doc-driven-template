# LE-01 Task Schema and Status Discipline

## Goal

Nuxt Content の task Markdown を、AI Agent が実装候補、承認状態、検証条件、handoff 条件を判断できる Reality Source にする。

この task の目的は、task schema を docs に書くだけではありません。AI Agent、Harness、Verifier が実装前に schema を通過し、schema に従わない task では実装を進めない状態を作ります。

## Scope

- Loop Engineering 用の task schema を docs に定義する。
- task status の値と遷移ルールを定義する。
- autonomy の値と扱いを定義する。
- verification commands と handoff conditions の書き方を定義する。
- Agent が実装前に task schema を読むように `SKILL.md` の Required Reading と stop rule を更新する。
- `docs/content/delivery/3.implementation-flow.md` に pre-implementation schema gate を追加する。
- Harness に task schema を検証する command を追加する。
- `package.json` に task validation command を追加する。
- Verifier checklist に schema compliance の確認を追加する。
- この scope の task page を schema に合わせる。
- 既存 MVP task への一括移行は、必要最小限の例示または方針記述に留める。

## Out of Scope

- 既存 task 全件の完全移行。
- Harness の full Markdown semantic parser 実装。
- Active Loop Dashboard の UI 実装。
- GitHub Actions の変更。
- Maker / Verifier agent prompt file の追加。
- PR 自動作成。

## Acceptance Criteria

- task schema の必須 field が docs に定義されている。
- 必須 field は少なくとも `id`、`status`、`autonomy`、`source_of_truth`、`primary_area`、`acceptance_criteria`、`verification_commands`、`handoff_conditions`、`last_evidence` を含む。
- status の候補値と意味が定義されている。
- status は `planned`、`approved`、`in_progress`、`verifying`、`resolved`、`blocked` を基本とする。
- autonomy の候補値と意味が定義されている。
- autonomy は `manual`、`assisted`、`autonomous` を基本とする。
- verification commands と handoff conditions の書き方が定義されている。
- `SKILL.md` に、Agent が実装前に task schema と approved target task を読む rule が追加されている。
- `SKILL.md` に、必須 field が欠ける task では実装を止める rule が追加されている。
- Implementation Flow に pre-implementation schema gate が追加されている。
- Harness が task Markdown の required fields、status、autonomy、source_of_truth、verification_commands、handoff_conditions を検証できる。
- `package.json` から task validation command を実行できる。
- Verifier checklist に schema compliance、status gate、autonomy gate、primary_area、verification_commands、handoff_conditions の確認が含まれる。
- この scope の task page が定義した schema と矛盾していない。
- 将来 scope の詳細 task を追加していない。

## Verification

```bash
node --check scripts/loop-harness.mjs
pnpm loop:validate-task LE-01
pnpm loop:validate-tasks
pnpm --dir docs typecheck
```

Verifier は、task schema とこの scope の task page を読み、field と status discipline が矛盾していないことを確認します。

Verifier must also confirm:

- target task has all required schema fields,
- task status allowed the performed operation,
- autonomy level matched the action,
- implementation stayed inside `primary_area`,
- `verification_commands` were run or a blocker was recorded,
- `handoff_conditions` were checked.

## Docs Update

task schema や status discipline を変更した場合は、maintenance、implementation flow、operations、`SKILL.md` の関連記述を更新します。
