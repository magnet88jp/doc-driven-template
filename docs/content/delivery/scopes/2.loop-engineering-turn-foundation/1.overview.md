# Loop Engineering Turn Foundation Overview

この scope は、Loop Engineering Implementation Roadmap を、Nuxt Content と Harness で実行可能な開発計画へ落とし込む phase です。

## Goal

Nuxt Content を Reality Source とし、人間と AI Agent が同じ docs を見ながら、1 turn の対象、意図、承認状態、実装範囲、検証条件、handoff 条件を確認できる状態を作ります。

この scope では、次の turn model を実装可能な単位へ分解します。

```txt
discover -> brief -> approve -> make -> verify -> persist -> schedule
```

## Product Boundary

この scope の product boundary は Loop Engineering の実行基盤です。

- 対象は `docs/content/delivery/` の task schema、Loop state、Harness brief 生成です。
- 人間向けの把握画面は Nuxt Content 上の docs として扱います。
- Maker / Verifier の実装支援は docs と Harness の出力に限定します。
- Web service 本体の機能追加、AWS リソース変更、認証、デプロイ自動化はこの scope の product boundary 外です。

## Gap From Target Design

現在の repository には Loop Engineering の設計 docs、`STATE.md`、`scripts/loop-harness.mjs`、L1/L2/L3 gate が存在します。

ただし、target design に対して次の gap があります。

- task Markdown に status、autonomy、verification commands、handoff conditions などの共通 schema がない。
- `STATE.md` が候補一覧、実行ログ、証跡を同時に背負っており、人間にも Agent にも扱いづらい。
- Harness が changed docs を候補化するだけで、task 単位の brief を生成できない。
- Maker と Verifier が参照する checklist が task から機械的に生成されない。
- Nuxt Content 上で active loop、blocked item、last evidence を追うための土台が不足している。

## Task Order

1. LE-01 で task schema と status discipline を定義する。
2. LE-02 で `STATE.md`、`.loop/state.json`、`.loop/runs/*.md` の責務を分離する。
3. LE-03 で `pnpm loop:brief <task-id>` を実装し、Maker / Verifier が同じ brief を読める状態にする。

Active Loop Dashboard、GitHub Actions の turn 単位化、低リスク task の自動 PR 化は、この scope の成果を確認してから次 scope で扱います。

## Scope Discipline

- この scope は Loop Engineering の foundation に限定する。
- task page は開始時点で実装するものだけを作る。
- Planned phase や将来 scope の詳細 task は先に作りすぎない。
- docs と Harness の変更は必ず対応する acceptance criteria と verification commands を持つ。
- secret、credential、token、`.env`、deployment credentials は読まない、書かない。
- 実装が scope を広げる場合は、先に delivery docs を更新する。

## Out of Scope

- Web service 本体の新機能追加。
- AWS SAM、Amplify、DynamoDB、IAM、deployment pipeline の変更。
- GitHub API を使った PR 自動作成。
- 自動 merge。
- L3 完全自律運用。
- 認証、secret、credential、token、`.env`、`.env.*` の読み取りまたは編集。
- 将来 scope の詳細 task 作成。

## Completion Rule

この scope は、task schema、state separation、brief generation が docs と Harness に反映され、Verifier が command evidence を残せる状態になったら完了です。
