# MVP Acceptance Criteria

MVP scope は、次の条件を満たしたときに受け入れ可能です。

## Criteria

- `docs/content` が design、operations、delivery に分かれている。
- design に理想形、責務境界、アーキテクチャが書かれている。
- operations に Getting Started、Initial Setup、日次、週次、月次、アドホック対応、環境情報、ドキュメント更新手順が書かれている。
- Getting Started に、AI Agent に docs を整理させるためのプロンプトサンプルが含まれている。
- Initial Setup が `apps` 配下のプログラムのセットアップ手順として分離されている。
- delivery にロードマップ、現在スコープ、実装フロー、MVP タスク、受け入れ条件が書かれている。
- maintenance に Loop Engineering の状態管理、検証証跡、PR ライフサイクルが書かれている。
- Loop Engineering が L1、L2、L3 を一連のパイプラインとして説明している。
- Maker と Verifier の責務が分離され、Verifier の完了判定には command evidence が必要である。
- Implementation Flow に AI Agent への標準指示テンプレートが含まれている。
- 各タスクが Goal、Scope、Out of Scope、Primary Area、Acceptance Criteria、Verification、Docs Update、Notes を持つ。
- Nuxt Content として frontmatter 付き Markdown が読み込める。

## Verification

docs サイトの build または Nuxt Content の読み込み確認を行います。実行できない場合は、未実施理由を実装報告に明記します。
