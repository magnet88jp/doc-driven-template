# MVP-10 Harness PR Brief Generation

## Goal

Loop Engineering Harness を強化し、candidate ID を指定すると、対象 docs、関連 docs、STATE.md の状態を読み取り、実装前レビューや PR 作成に使える brief とチェックリストを生成できるようにします。

このタスクは、L3 完全自動化の前段として、人間が実装意図、Scope、Verifier 条件、Handoff 条件を確認しやすくすることを目的とします。

## Scope

- Harness に candidate ID を入力するコマンドを追加する。
- `STATE.md` から candidate item を検索する。
- candidate の source docs を特定する。
- 対象 task の Related Docs を読み取る。
- Current Scope、Implementation Flow、対象 task、関連 design / operations / maintenance の参照リストを生成する。
- PR 本文のドラフトを生成する。
- Maker チェックリストを生成する。
- Verifier チェックリストを生成する。
- Handoff 条件を生成する。
- 生成結果は標準出力または repository 内の一時的な Markdown として確認できるようにする。
- 生成物には secret、credential、token、`.env` の値を含めない。

## Out of Scope

- PR の自動作成。
- GitHub API 呼び出し。
- 自動 commit。
- 自動 merge。
- 実装コードの自動生成。
- secret、credential、token、`.env`、`.env.*` の読み取り。
- L3 完全自動化。

## Functional Requirements

### Command

Add a command similar to:

```bash
pnpm loop:brief -- <candidate-id>
```

or:

```bash
pnpm loop:brief <candidate-id>
```

The exact command shape may follow the existing Harness style, but it must be documented.

### Candidate Resolution

Harness must:

- find the candidate row by ID in `STATE.md`,
- extract source docs,
- identify stage, approval status, attempts, impact area, maker action, and verifier evidence,
- fail with a clear message if the candidate ID is unknown.

### Docs Reading

Harness must include references to:

- Current Scope,
- Implementation Flow,
- target source docs,
- Related Docs listed in the target task,
- Loop Engineering design docs when the candidate is a loop task.

Harness should not attempt to summarize large files aggressively. The first version may generate a reference list and checklist rather than a full semantic summary.

### PR Brief

The generated brief must include:

- candidate ID,
- source docs,
- intended autonomy tier,
- scope summary,
- out of scope summary,
- expected changed areas,
- verifier commands,
- denylist reminder,
- handoff triggers,
- unchecked assumptions.

### Maker Checklist

The generated Maker checklist must include:

- required docs read,
- scope confirmation,
- denylist check,
- implementation area,
- docs update requirement,
- commands to run before handing off to Verifier.

### Verifier Checklist

The generated Verifier checklist must include:

- diff review,
- acceptance criteria review,
- command evidence,
- docs-code consistency check,
- handoff condition check.

## Acceptance Criteria

- Candidate ID を指定して brief を生成できる。
- Unknown candidate ID では明確に失敗する。
- brief に対象 docs と関連 docs が含まれる。
- brief に Maker checklist が含まれる。
- brief に Verifier checklist が含まれる。
- brief に Handoff triggers が含まれる。
- secret、credential、token、`.env` の値を読まない。
- `node --check scripts/loop-harness.mjs` が通る。
- Harness のコマンド説明が docs または root scripts に反映されている。

## Verification

Maker runs:

```bash
node --check scripts/loop-harness.mjs
pnpm loop:brief <candidate-id>
```

Verifier runs:

```bash
pnpm loop:verify:harness
```

Verifier also checks:

- generated brief contains candidate ID,
- generated brief contains source docs,
- generated brief contains Maker and Verifier checklists,
- generated brief does not include secret-like values.

## Notes

This task improves human involvement. The goal is not to remove human review, but to make the review target explicit before implementation begins.
