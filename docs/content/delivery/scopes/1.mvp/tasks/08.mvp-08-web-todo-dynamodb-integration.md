# MVP-08 Web ToDo DynamoDB Integration

## Goal

MVP-05 で作成した ToDo リストを、MVP-07 の SAM output で提供される DynamoDB table に接続します。

このタスクは、Web app の server API と UI を更新し、ToDo の一覧取得、作成、完了切り替え、削除を DynamoDB 経由で行えるようにすることを目的とします。

## Prerequisites

- MVP-07 が完了している。
- ToDo DynamoDB table name が SAM output または docs で確認できる。
- AWS region が確認できる。
- ローカルまたは実行環境に DynamoDB へアクセスできる AWS credentials が設定済みである。
- credentials や secret は repository に書かない。

## Scope

- `apps/web` に ToDo server API を追加する。
- ToDo page を server API 連携に更新する。
- DynamoDB table name と AWS region は runtime config または環境変数から読む。
- ToDo の一覧取得、作成、完了切り替え、削除を DynamoDB に永続化する。
- 入力検証を server API 側で行う。
- API または DynamoDB 操作失敗時のエラー表示を UI に追加する。
- 読み込み中状態を UI に追加する。
- MVP-05 の UX と基本機能を維持する。

## Out of Scope

- DynamoDB table の作成または変更。
- SAM template の変更。
- IAM policy の変更。
- AWS credentials、secret、token、`.env`、`.env.*` の自動編集。
- 認証、ユーザー別 ToDo、マルチテナント対応。
- オフライン同期。
- リアルタイム同期。
- 本番デプロイ。

## Primary Area

- `apps/web/app/pages/todos.vue`
- `apps/web/server/api/`
- 必要に応じて `apps/web/app/types/`
- 必要に応じて `apps/web/nuxt.config.ts`
- 必要に応じて `apps/web/package.json`

## API Requirements

The server API must support:

- list ToDos,
- create ToDo,
- update completion state,
- delete ToDo.

Server API must:

- validate input,
- reject empty or whitespace-only titles,
- hide DynamoDB implementation details from the client,
- return stable error responses the UI can display,
- keep DynamoDB operations server-side only.

## UI Requirements

The ToDo page must preserve:

- add ToDo,
- toggle completed / active,
- delete ToDo,
- filter by `All`, `Active`, `Completed`,
- active and completed counts,
- empty state.

The page must add:

- initial loading state,
- operation pending state where appropriate,
- visible error state when API or DynamoDB operations fail,
- recovery path after failure.

## Acceptance Criteria

- ToDos are loaded from the server API.
- New ToDos are written to DynamoDB through the server API.
- Completion changes are persisted to DynamoDB through the server API.
- Deleted ToDos are removed from DynamoDB through the server API.
- Empty or whitespace-only titles are rejected server-side.
- UI shows loading and error states.
- No denylisted files are changed.
- No SAM, IAM, credential, secret, `.env`, or deployment file is changed.
- Verifier evidence is recorded in `STATE.md` or PR output.

## Verification

Maker runs:

```bash
pnpm --dir apps/web typecheck
pnpm --dir apps/web lint
```

Verifier runs:

```bash
pnpm loop:verify:web
```

If AWS credentials, table name, or region are unavailable, Verifier records the missing prerequisite and hands off instead of marking the item complete.

Where possible, Verifier also confirms:

- server API handlers validate input,
- DynamoDB operations are isolated to server-side code,
- UI handles loading and error states,
- denylisted paths were not changed.

## L2 / L3 Policy

This task may be tested as L3 gated execution only after MVP-07 has produced the table name and region. If those prerequisites are missing, L3 must hand off.

## Notes

MVP-08 is the integration step. It must not create cloud resources; it consumes the DynamoDB resource provisioned by MVP-07.
