# MVP-04 Loop Engineering Pipeline

## Goal

Build the Loop Engineering foundation as a pipeline from Nuxt Content changes to impact analysis, approved implementation, verifier evidence, and future PR creation.

## Scope

- Add Loop Engineering architecture docs under Nuxt Content.
- Define L1, L2, L3 responsibilities as one pipeline.
- Define Maker and Verifier responsibilities.
- Define Harness behavior and state transitions.
- Add root Harness commands and GitHub Actions L1 trigger.
- Use `STATE.md` as follow-up loop state, not just a log.

## Out of Scope

- Full autonomous L3 implementation.
- Automatic merge.
- Secret, credential, authentication, or deployment changes.

## Primary Area

- `docs/content/design/4.loop-engineering/`
- `docs/content/operations/10.loop-engineering.md`
- `docs/content/maintenance/`

## Acceptance Criteria

- Loop Engineering is documented as an end-to-end L1 -> L2 -> L3 pipeline.
- Nuxt Content remains the Reality Source.
- `STATE.md` includes candidate state, active work, verifier evidence, resolved items, and handoff queue.
- Harness supports L1 analysis and gates L2/L3 behind explicit approval.
- Verifier commands are exposed through package scripts.
- GitHub Actions runs L1 on docs content changes and scheduled triage.

## Verification

- `node --check scripts/loop-harness.mjs`
- `pnpm loop:l1`
- `pnpm loop:l2` without approval must block and record handoff state.
- `pnpm loop:verify:harness`
- `pnpm --dir docs typecheck`

## Docs Update

Update design, operations, delivery, and maintenance docs when loop behavior changes.
