# Task Title

MVP-03 Shared Contract Baseline

## Goal

API 入出力、共通型、エラー形式などを確認し、`packages/shared` を追加すべきか判断できる baseline を作る。

## Scope

- `apps/web` 内の API 型、DTO、共通ユーティリティを確認する。
- 複数領域で共有すべき契約候補を洗い出す。
- 必要であれば `packages/shared` の最小構成を提案または実装する。
- 共有契約の配置ルールを docs と整合させる。

## Out of Scope

- ドメインモデルの大規模再設計。
- 全 API の一括移行。
- バッチアプリや infra の実装。
- 仕様が未確定な型の過剰な共通化。

## Primary Area

`packages/shared`

## Acceptance Criteria

- 共有契約として扱う対象と対象外が明確になっている。
- `packages/shared` を追加する場合、依存方向が design の monorepo 方針と合っている。
- 破壊的変更がある場合、影響範囲と検証方法が delivery に書かれている。
- 共有化しない判断をした型についても、理由が Notes または delivery に残っている。

## Verification

- 型チェックまたは build で依存関係が壊れていないことを確認する。
- 共有契約を利用する API または UI の動作を確認する。
- docs の shared contracts 記述と実装配置が一致していることを確認する。

## Docs Update

共有契約の責務や配置方針が変わる場合は design を更新する。導入手順や検証手順が標準化される場合は operations を更新する。移行範囲は delivery に記録する。

## Notes

共有化は目的ではなく、意味の重複や契約ずれを防ぐために行う。
