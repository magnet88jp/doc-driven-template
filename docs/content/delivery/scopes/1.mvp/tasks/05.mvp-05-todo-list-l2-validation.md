# MVP-05 ToDo List L2 Validation

## Goal

Loop Engineering の L2 フローを、小さな Web アプリケーション実装で検証します。

Nuxt Content に書いた要件を Reality Source とし、L1 で影響分析、L2 で承認済み実装、Verifier で証拠付き検証まで進められることを確認します。

## Scope

- `apps/web` に ToDo リスト画面を追加する。
- ToDo はブラウザ内のローカル状態で管理する。
- ユーザーは ToDo を追加、完了/未完了に切り替え、削除できる。
- フィルターで `All`、`Active`、`Completed` を切り替えられる。
- 件数サマリーとして、未完了数と完了数を表示する。
- 入力が空、または空白だけの場合は追加しない。
- ページをリロードすると状態は失われてよい。
- 既存の `apps/web` の Nuxt UI / Vue patterns に合わせる。

## Out of Scope

- 認証。
- 永続DB。
- API追加。
- 複数ユーザー対応。
- ドラッグアンドドロップ。
- 期限、通知、カレンダー連携。
- モバイル専用の複雑なジェスチャー。
- デプロイ設定変更。

## Primary Area

- `apps/web/app/pages/`
- 必要に応じて `apps/web/app/components/`
- 必要に応じて `apps/web/app/types/`

## Functional Requirements

### ToDo Entry

- 画面上部に ToDo タイトル入力欄と追加ボタンを置く。
- Enter キー、または追加ボタンで ToDo を追加できる。
- 追加後、入力欄は空になる。
- 空文字と空白だけの入力は無視する。

### ToDo List

- 追加した ToDo は一覧に表示される。
- 各 ToDo はタイトル、完了切り替え、削除操作を持つ。
- 完了済み ToDo は未完了 ToDo と視覚的に区別できる。
- ToDo がない場合は空状態を表示する。

### Filters

- `All` は全件を表示する。
- `Active` は未完了だけを表示する。
- `Completed` は完了済みだけを表示する。
- 現在選択中のフィルターが分かる表示にする。

### Summary

- 未完了数を表示する。
- 完了数を表示する。
- ToDo が増減、または完了状態が変わるとサマリーも更新される。

## UX Requirements

- 最初の画面で ToDo の追加、一覧、フィルター、サマリーが見える。
- 業務ツールとして静かで実用的な見た目にする。
- 既存の `apps/web` のレイアウト、余白、コンポーネント利用方針から大きく外れない。
- ボタンには用途が分かるラベルまたはアイコンを使う。
- モバイル幅でも入力欄、ボタン、一覧のテキストが重ならない。

## Acceptance Criteria

- ToDo を追加できる。
- 空文字と空白だけの入力では ToDo が追加されない。
- ToDo を完了済みにできる。
- 完了済み ToDo を未完了へ戻せる。
- ToDo を削除できる。
- `All`、`Active`、`Completed` フィルターが期待通りに動く。
- 未完了数と完了数が正しく表示される。
- ToDo がない状態が破綻せず表示される。
- 実装は `apps/web` に限定され、denylist には触れない。
- 実装後に Verifier が command evidence を残せる。

## Verification

Maker は実装後に次を実行します。

```bash
pnpm --dir apps/web typecheck
pnpm --dir apps/web lint
```

Verifier は独立したコンテキストで次を実行します。

```bash
pnpm loop:verify:web
```

Verifier は、少なくとも次を手動確認またはコード確認として報告します。

- 空入力が追加されない。
- 追加、完了切り替え、削除、フィルター、サマリーの状態更新が実装されている。
- denylist に該当するファイルを変更していない。

## L2 Validation Flow

1. この task を追加または更新する。
2. `pnpm loop:l1` を実行する。
3. `STATE.md` の candidate item からこの task の ID を確認する。
4. 人間が candidate item を L2 実装対象として承認する。
5. `LOOP_APPROVED_ITEM_ID=<candidate-id> LOOP_ENABLE_AUTONOMY=l2 pnpm loop:l2` を実行する。
6. Maker がこの task の Scope に限定して実装する。
7. Verifier が `pnpm loop:verify:web` を実行し、証拠付きで合否を判断する。

## Notes

この task は L2 検証用です。機能の完成度よりも、Reality Source から実装、検証、証跡記録までの流れを確認することを優先します。
