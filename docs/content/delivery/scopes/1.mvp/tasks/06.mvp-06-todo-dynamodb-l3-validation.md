# MVP-06 ToDo DynamoDB L3 Validation

## Goal

Loop Engineering の L3 相当の検証として、MVP-05 で作成した ToDo リストを、AWS SAM で作成済みの DynamoDB を使う構成へ更新します。

このタスクでは、Nuxt Content の要件を Reality Source とし、Loop が影響分析、実装判断、Maker 実装、Verifier 証拠付き検証、必要な docs 更新、PR 準備へ進めるかを確認します。

実装は、DynamoDB を作成する MVP-07 と Web 連携を行う MVP-08 に分割して進めます。

## Assumptions

- DynamoDB テーブルは AWS SAM によって作成済みである。
- このリポジトリに SAM テンプレートが存在しない場合、Loop はテーブル作成を行わず、人間へ必要情報を確認する。
- 実行環境には DynamoDB へアクセスできる AWS credentials が設定済みである。
- ToDo リストの既存 UI は MVP-05 の成果物を前提にする。
- L3 検証では、低リスク範囲に限定して自動化を試す。認証情報、デプロイ、秘密情報、IAM 変更は自動化しない。

## Scope

- 既存 ToDo リストを DynamoDB 永続化に対応させる。
- `apps/web` の server API を通じて ToDo の一覧取得、作成、完了切り替え、削除を行う。
- ブラウザ側は server API を呼び出し、ローカル状態だけに依存しない。
- DynamoDB の table name と region は runtime config または環境変数から読む。
- UI は MVP-05 の要件を維持する。
- DynamoDB 接続に失敗した場合、画面上で操作不能にならないようにエラー状態を表示する。
- Verifier が typecheck、lint、必要に応じた手動確認または mock 確認を証拠として残せるようにする。
- 実装で Reality Source と差分が出た場合は、関連 docs を更新する。

## Out of Scope

- DynamoDB テーブルの新規作成。
- SAM テンプレートの新規作成または変更。
- IAM policy の変更。
- AWS credentials、secret、token、`.env`、`.env.*` の自動編集。
- 認証、ユーザー別 ToDo、マルチテナント対応。
- リアルタイム同期。
- オフライン同期。
- 本番デプロイ。
- 自動 merge。

## Functional Requirements

### Data Model

Each ToDo item should have:

- `id`: stable string identifier.
- `title`: non-empty string.
- `completed`: boolean.
- `createdAt`: ISO timestamp.
- `updatedAt`: ISO timestamp.

The implementation may add a partition key field if the existing DynamoDB table requires it.

### Server API

The server API should support:

- list ToDos,
- create ToDo,
- update completion state,
- delete ToDo.

API handlers must validate input before writing to DynamoDB. Empty or whitespace-only titles must be rejected.

### Web UI

The ToDo page must preserve MVP-05 behavior:

- add ToDo,
- toggle completed / active,
- delete ToDo,
- filter by `All`, `Active`, `Completed`,
- show active and completed counts,
- show empty state.

The page must additionally:

- show loading state while fetching ToDos,
- show an error state when the API or DynamoDB operation fails,
- keep the UI responsive after a failed operation.

## L3 Validation Requirements

L3 may be tested only if:

- `STATE.md` contains the MVP-06 candidate item from L1.
- The candidate is low-risk and does not require denylisted paths.
- A human explicitly enables L3 with `LOOP_ENABLE_AUTONOMY=l3`.
- The loop does not create or modify secrets, credentials, IAM, or deployment files.
- Verifier command evidence is recorded before the item is considered complete.

This task is acceptable for L3 dry run or L3 gated execution. It is not acceptable for unsupervised production deployment.

## Acceptance Criteria

- Existing ToDo UI still supports add, toggle, delete, filter, and summary.
- ToDos are loaded from the server API.
- New ToDos are written through the server API to DynamoDB.
- Completion changes are persisted through the server API to DynamoDB.
- Deleted ToDos are removed through the server API from DynamoDB.
- Empty or whitespace-only titles are rejected.
- Loading and error states are visible.
- No denylisted files are modified.
- No SAM, IAM, credential, secret, `.env`, or deployment file is changed automatically.
- Verifier evidence is recorded in `STATE.md` or PR output.

## Verification

Maker runs:

```bash
pnpm --dir apps/web typecheck
pnpm --dir apps/web lint
```

Verifier runs:

```bash
pnpm loop:verify:web
```

If AWS credentials or table information are unavailable, Verifier records the missing prerequisite and hands off instead of marking the item complete.

Where possible, Verifier also confirms:

- server API handlers validate input,
- DynamoDB operations are isolated to server-side code,
- UI handles loading and error states,
- denylisted paths were not changed.

## L3 Execution Flow

1. Run `pnpm loop:l1` after adding this task.
2. Identify the candidate item for `06.mvp-06-todo-dynamodb-l3-validation.md` in `STATE.md`.
3. Run the L3 gate:

```bash
LOOP_APPROVED_ITEM_ID=<candidate-id> LOOP_ENABLE_AUTONOMY=l3 pnpm loop:l3
```

4. If the gate is ready, allow Maker to implement only this task's Scope.
5. Verifier runs `pnpm loop:verify:web`.
6. If DynamoDB access cannot be verified locally, record the blocker and hand off to a human.
7. Prepare PR summary only after verifier evidence exists.

## Notes

This task intentionally introduces a real external dependency. That makes it useful for L3 validation, but it also raises the risk level. The loop must prefer handoff over unsafe guesses when table names, AWS region, credentials, or SAM outputs are unknown.
