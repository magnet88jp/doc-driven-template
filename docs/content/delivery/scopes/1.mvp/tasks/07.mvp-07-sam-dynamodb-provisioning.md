# MVP-07 SAM DynamoDB Provisioning

## Goal

ToDo リスト永続化に使う DynamoDB テーブルを、AWS SAM の `infra/aws/sam/template.yaml` で管理できる状態にします。

このタスクは、DynamoDB リソース定義と SAM build/deploy の検証を目的とします。Web アプリから DynamoDB を利用する実装は MVP-08 で扱います。

## Scope

- `infra/aws/sam/template.yaml` を作成または更新する。
- ToDo 用 DynamoDB table を SAM template に定義する。
- Table name は環境ごとに衝突しにくい名前にする。
- ToDo item の primary key を定義する。
- Billing mode は MVP 用にオンデマンドを基本とする。
- `Outputs` に Web 連携で参照できる table name を出力する。
- 必要に応じて `infra/aws/sam/samconfig.toml` または運用 docs に stack name、region、deploy 手順を記述する。
- `package.json` の既存 `sam:build`、`sam:deploy` scripts と整合する構成にする。

## Out of Scope

- Web アプリから DynamoDB を呼び出す実装。
- ToDo API の追加。
- AWS credentials、secret、token、`.env`、`.env.*` の自動編集。
- 既存の本番リソース削除。
- 認証、ユーザー別データ分離、マルチテナント対応。
- L3 完全自動 deploy。

## DynamoDB Requirements

The table must support ToDo items with:

- `id`: stable string identifier and primary key.
- `title`: non-empty string.
- `completed`: boolean.
- `createdAt`: ISO timestamp.
- `updatedAt`: ISO timestamp.

The first MVP table may use a simple partition key:

- Partition key: `id` as `S`

If an environment or tenant partition is needed later, it must be introduced through a separate docs update and task.

## SAM Requirements

- Template format must be valid AWS SAM / CloudFormation YAML.
- DynamoDB table must be represented as an explicit resource.
- Output must include the table name.
- Destructive changes must not be introduced.
- Deploy command must be human-approved before execution.

## Acceptance Criteria

- `infra/aws/sam/template.yaml` exists.
- SAM template defines a ToDo DynamoDB table.
- Table primary key is documented in the template or related docs.
- SAM output exposes the table name.
- `pnpm sam:build` succeeds or a concrete blocker is recorded.
- `pnpm sam:deploy` is executed only after human approval.
- No credentials, secrets, or `.env` files are changed.
- Verifier evidence is recorded in `STATE.md` or PR output.

## Verification

Maker runs:

```bash
pnpm sam:build
```

Verifier runs:

```bash
pnpm sam:build
```

Deploy requires explicit human approval:

```bash
pnpm sam:deploy
```

If AWS credentials, region, stack name, or deploy confirmation are unavailable, Verifier records the missing prerequisite and hands off instead of marking deploy complete.

## L2 / L3 Policy

This task is suitable for L2 implementation. It is not suitable for unsupervised L3 deployment because it can create or modify cloud resources.

L3 may only perform dry-run style checks for this task unless a human explicitly authorizes deploy for the current run.
