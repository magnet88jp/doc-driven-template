# Implementation Flow

Implementation Flow は、AI Agent が実装前後に従う標準手順です。実装は docs で合意された範囲に限定します。

## Required Reading

AI Agent は実装前に必ず以下を読みます。

1. Current Scope: `docs/content/delivery/2.current-scope.md`
2. Target Task: `docs/content/delivery/scopes/**/tasks/*.md`
3. Implementation Flow: `docs/content/delivery/3.implementation-flow.md`

## AI Agent Prompt Template

```txt
次のタスクを実装してください。

まず以下の docs を読んで、現在スコープ、対象タスク、実装フローを確認してください。

Current Scope:
docs/content/delivery/2.current-scope.md

Task:
docs/content/delivery/scopes/1.mvp/tasks/XX.task-name.md

Implementation Flow:
docs/content/delivery/3.implementation-flow.md

実装後は、変更内容に応じて design / operations / delivery の該当 docs を更新してください。
```

## Implementation Steps

1. Current Scope を読み、今回の作業が In Scope か確認する。
2. 対象 Task を読み、Goal、Scope、Out of Scope、Acceptance Criteria、Verification を確認する。
3. design の関連ページを読み、責務境界と理想設計を確認する。
4. 対象コードと既存 docs を確認する。
5. 実装する。
6. Verification に書かれた確認を実行する。
7. 変更内容に応じて docs を更新する。
8. 実装結果、検証結果、未実施の検証を報告する。

## Docs Update Matrix

| 変更内容 | 更新先 |
| --- | --- |
| 理想設計、責務境界、アーキテクチャが変わる | `design` |
| 標準手順、環境情報、運用確認が変わる | `operations` |
| 現在スコープ、タスク、受け入れ条件が変わる | `delivery` |
| 実装だけが変わり合意内容は変わらない | docs 更新なしでもよい |

## Guardrails

- Task の Out of Scope に含まれる作業を実装しない。
- 仕様が docs にない場合は、既存設計から導ける最小限に留める。
- 大きな判断変更は、コードより先に docs を更新する。
- 実装後に docs とコードが矛盾していないか確認する。
