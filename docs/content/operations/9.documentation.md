# Documentation Operations

docs 更新は、実装と同じ開発成果物として扱います。

## 更新手順

1. 変更が design、operations、delivery のどこに影響するか確認する。
2. 該当する Markdown を更新する。
3. title、description、navigation icon を含む frontmatter を保つ。
4. docs サイトが Nuxt Content として読める構造を保つ。
5. 実装後の検証結果と docs の内容が矛盾していないか確認する。

## 置き場所の判断

- 理想形、責務境界、アーキテクチャ: `design`
- 標準手順、環境情報、運用確認: `operations`
- 現在スコープ、差分、タスク、受け入れ条件: `delivery`

## AI Agent へのルール

実装後に docs を更新する場合、現在のタスク完了に必要な範囲へ絞ります。無関係な設計刷新や文体変更を混ぜません。
