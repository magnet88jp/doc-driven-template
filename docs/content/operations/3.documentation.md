# Documentation Operations

Documentation Operations は、AI Agent が docs を作成、分類、更新するときの標準手順です。

docs の責務境界、矛盾時の優先順位、最低構成は `design/overview/documentation-governance` に従います。このページでは、AI Agent が迷わず行動するための実務ルールだけを扱います。

## 基本方針

- docs 更新は、実装と同じ開発成果物として扱う。
- 更新前に内容を分類し、反映先を判断する。
- 利用者が docs の置き場所を指定していなくても、AI Agent が適切な置き場所を選ぶ。
- 大きな判断変更は、コードより先に docs へ反映する。
- 実装後は、Verification と Acceptance Criteria に照らして docs と実装が矛盾していないか確認する。

## AI Agent 向け分類ルール

AI Agent は、利用者の説明を受けたら、まず次の分類に分けます。

1. 理想設計: 長期的に目指す構成、責務、判断基準。
2. 標準手順: 繰り返し使う作業、確認、運用ルール。
3. 現在スコープ: 今回作る範囲、今回は作らない範囲、前提。
4. タスク: 実装可能な単位に分けた作業。
5. 受け入れ条件: 何が確認できれば完了と言えるか。

分類できない情報がある場合は、無理に docs へ書き込まず、追加質問または仮置きの前提として扱います。利用者に docs の置き場所を尋ねるのではなく、何を実現したいのか、今決めたいのか、後回しにしたいのかを確認します。

## 実装前の読書順

AI Agent は、実装前に次の順序で docs を読みます。

1. `delivery/current-scope`
2. 対象タスク
3. 関連する `design`
4. 関連する `operations`

`delivery/current-scope` は AI Agent の作業開始地点です。Current Scope で今回作る範囲、今回は作らない範囲、前提、検証方針を確認してから対象タスクへ進みます。

## docs が不足している場合の行動

AI Agent は、次のいずれかに該当する場合、実装を開始しません。

- Current Scope が存在しない。
- タスクが存在しない。
- Acceptance Criteria が存在しない。
- Scope が不明確。

この場合は、不足している docs の作成または更新を提案します。利用者が実装を急いでいる場合でも、完了判断に必要な Scope、Out of Scope、Acceptance Criteria、Verification が確認できる状態にしてから実装します。

## 質問が必須な条件

AI Agent は、次の場合に勝手に仮定せず、利用者へ質問します。

- In Scope が不明。
- Out of Scope が不明。
- Acceptance Criteria が不明。
- 複数の解釈が可能。
- docs 間で矛盾がある。

質問する場合は、docs の置き場所ではなく、実現したい結果、今回含める範囲、今回含めない範囲、完了条件を確認します。

## AI Agent が更新してよい範囲

AI Agent は、現在の依頼に直接関係する docs のみ更新します。

次の更新は禁止します。

- 無関係な architecture 更新。
- 無関係な設計刷新。
- 大規模な文体変更。
- ページ構造変更。

これらが必要だと判断した場合は、現在の依頼には混ぜず、別タスクとして提案します。

## 更新先の決め方

AI Agent は、更新前に次の順序で判断します。

1. 今回作る範囲、作らない範囲、完了条件に関係するか。
2. 理想設計、責務境界、長期判断に関係するか。
3. 繰り返し使う手順、環境情報、運用確認に関係するか。
4. 実装だけが変わり、docs の合意内容は変わらないか。

判断結果に応じて、`delivery`、`design`、`operations` のいずれかを更新します。責務境界そのものに迷う場合は、`design/overview/documentation-governance` を確認します。

## Current Scope を中心とした開発サイクル

AI Agent は、Current Scope を作業開始地点として扱います。

1. 実装前に `delivery/current-scope` を読み、今回の Scope、Out of Scope、前提、Verification を確認する。
2. 対象タスクを読み、Goal、Scope、Acceptance Criteria、Verification を確認する。
3. 関連する `design` と `operations` を読み、責務境界と標準手順を確認する。
4. 実装する。
5. 実装後に Verification と Acceptance Criteria を確認する。
6. 実装結果と docs がずれている場合は、現在の依頼に直接関係する docs の更新だけを行う。
7. Acceptance Criteria を満たしていることを確認してから完了判断を行う。

## AI Agent への標準依頼パターン

### 新規プロジェクト開始

```txt
このリポジトリで作りたいものを説明します。
まずコードは変更せず、必要であれば追加質問してください。
その後、design、operations、delivery を整理してください。
docs の置き場所は AI Agent が判断してください。
```

### 設計思想作成

```txt
作りたいものを元に、理想設計と判断基準を整理してください。
現在スコープ、タスク、進捗は design に混ぜず、必要に応じて delivery に分けてください。
```

### スコープ追加

```txt
次に作りたい範囲を追加したいです。
理想設計との差分、In Scope、Out of Scope、受け入れ条件を整理してください。
必要な design / operations の更新があればあわせて提案してください。
```

### タスク作成

```txt
現在スコープを、AI Agent が実装できるタスク単位に分解してください。
各タスクには Goal、Scope、Out of Scope、Acceptance Criteria、Verification を含めてください。
```

### 実装

```txt
次のタスクを実装してください。
実装前に Current Scope、対象タスク、関連する design / operations を読んでください。
実装後は検証し、docs と実装がずれていれば必要な docs を更新してください。
```

### docs 更新

```txt
次の変更内容を docs に反映してください。
design、operations、delivery のどこへ書くべきかは AI Agent が判断してください。
無関係な文体変更や設計刷新は混ぜないでください。
```

## 作業開始前チェック

AI Agent は、利用者の依頼を受けたら、すぐにファイルを書き換える前に次を確認します。

1. Current Scope と対象タスクは存在するか。
2. Scope、Out of Scope、Acceptance Criteria、Verification は確認できるか。
3. 関連する `design` と `operations` はどれか。
4. docs 間の矛盾や古い記述はあるか。
5. 利用者に質問しないと実装範囲を決められない点はあるか。

不足や矛盾がある場合は、実装前に docs の作成、更新、または利用者への質問を行います。利用者が置き場所を指定した場合でも、責務分離に反するなら、より適切な反映先を提案してから更新します。

## 更新手順

1. `design/overview/documentation-governance` を確認する。
2. 変更が `design`、`operations`、`delivery` のどこに影響するか確認する。
3. 該当する Markdown を更新する。
4. `title`、`description`、`navigation icon` を含む frontmatter を保つ。
5. docs サイトが Nuxt Content として読める構造を保つ。
6. 実装後の検証結果と docs の内容が矛盾していないか確認する。
