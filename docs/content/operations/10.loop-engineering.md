# Loop Engineering Operations

This page defines the repeatable operations for running Loop Engineering.

## L1 Local Run

After changing Nuxt Content docs:

```bash
LOOP_BUDGET_USD=10 LOOP_ESTIMATED_COST_USD=0 LOOP_MAX_ATTEMPTS=3 pnpm loop:l1
```

Expected result:

- `STATE.md` is updated as a compatibility mirror.
- `.loop/state.json` is updated with machine-readable latest state.
- `.loop/runs/*.md` receives a per-run log.
- `docs/content/delivery/loop-dashboard.md` is updated as the human-facing latest status page.
- Changed docs are listed as candidate items.
- No implementation files outside the documented loop state surfaces are modified by the harness.

## L2 Gate

After a human approves a candidate item:

```bash
LOOP_APPROVED_ITEM_ID=<candidate-id> LOOP_ENABLE_AUTONOMY=l2 pnpm loop:l2
```

L2 may proceed only after this gate passes. Maker then implements the approved scope and Verifier runs command evidence.

Expected result:

- The L2 gate result is mirrored in `STATE.md`.
- `.loop/state.json`, `.loop/runs/*.md`, and the Loop Dashboard are updated.
- If approval or enablement is missing, the dashboard shows a blocked gate and the next human action.

## Verifier Runs

Docs verification:

```bash
pnpm loop:verify:docs
```

Web verification:

```bash
pnpm loop:verify:web
```

Harness verification:

```bash
pnpm loop:verify:harness
```

Verifier records command results in `STATE.md`, `.loop/runs/*.md`, `.loop/state.json`, and the Loop Dashboard. PR bodies may summarize the same evidence later, but repository state remains the local source for this scope.

## State Surfaces

Use these surfaces for routine operation:

| Surface | Use |
| --- | --- |
| `docs/content/delivery/loop-dashboard.md` | Human-facing current turn and next action. |
| `.loop/state.json` | Machine-readable latest state. |
| `.loop/runs/*.md` | Run-by-run evidence history. |
| `STATE.md` | Compatibility mirror for existing candidate and evidence flows. |

The Harness must not read or write secrets, credentials, tokens, `.env`, or `.env.*` values when updating these surfaces.

## GitHub Actions

The L1 workflow runs on:

- pushes to `docs/content/**/*.md`,
- daily scheduled triage,
- manual workflow dispatch.

The workflow state write surface is `STATE.md`, `.loop/state.json`, `.loop/runs/*.md`, and `docs/content/delivery/loop-dashboard.md`. L2 and L3 PR automation must be added only after the promotion criteria in `design/4.loop-engineering/autonomy-tiers` are satisfied.
